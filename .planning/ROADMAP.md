# Roadmap: 키움멘토 릴스 제작 자동화

## Overview

기존 Python + Playwright + ffmpeg 렌더러를 새 클라우드 세션에서도 똑같이 돌아가게 고정하고, 기존 릴스로 회귀 기준을 세우는 것부터 시작한다. 그다음 주제 한 줄이나 카드뉴스 원고로 하우스 패턴 원고와 게시글 문구를 만든다. 이어서 금소법 표현 점검과 검수·승인 게이트를 붙여, 한 번 요청하면 10분 안에 검수 가능한 초안 묶음이 나오게 한다. Phase 3까지 끝나면 1순위인 제작 자동화가 완성된다. 마지막으로 2순위인 자막 모션과 선택 배경음을 같은 타임라인 위에 얹는다. 단계 사이에는 오너 결정 게이트가 있다. 금소법 광고 해당 여부·필수 고지와 표지 방식은 Phase 3 전에, 배경음 음원 라이선스는 Phase 4 전에 정해야 한다.

## Phase Details

### Phase 1: 렌더 기반 고정 (Render Foundation)
**Goal**: 새 클라우드 세션에서 추가 설치 없이 기존 형식 그대로 릴스를 다시 만들 수 있다. 새 릴스의 근거 표기와 계정명은 인스타그램 UI에 가려지지 않는다. 화면 깨짐과 업로드 규격 위반은 렌더 단계에서 바로 드러난다.
**Depends on**: Nothing (first phase)
**Requirements**: ENV-01, ENV-02, ENV-03, ENV-04, ENV-05, ENV-06
**Success Criteria** (what must be TRUE):
  1. 새 클라우드 세션에서 추가 설치 없이 사전 점검 명령 하나를 실행하면 Chromium 실행, 저장소에 포함된 한글 폰트 로드, ffmpeg 사용 가능 여부가 표시된다. 모두 정상이면 종료 코드 0이고, 하나라도 실패하면 원인 메시지가 나온다.
  2. 기존 릴스 원고 10편(`2026/reels/specs/*.json`)을 새 렌더러로 다시 만드는 회귀 시험을 실행하면, 편마다 길이·장면 경계·표지 시점이 기존과 같은지, 화면이 허용 오차 안에서 일치하는지 보고된다. 원고 없는 MP4(`2026-10-19-savings-interest.mp4`)는 "재현 불가"로 표기된다.
  3. 새로 만든 릴스에서 근거 표기와 계정명(@kiwoom.mentor)은 인스타그램 하단 UI 영역 밖에 36px 이상 글씨로 보인다. 안전영역 오버레이 미리보기 이미지로 이를 눈으로 확인할 수 있다.
  4. 줄 넘침, 줄바꿈 깨짐, 안전영역 침범이 있는 원고를 렌더하면 해당 장면과 줄을 가리키는 경고가 출력된다.
  5. 렌더된 MP4를 ffprobe 검사에 넣으면 1080×1920, 30fps, H.264 yuv420p, AAC, faststart 충족 여부가 항목별로 확인된다.
**Plans**: 4/4 plans executed

### Phase 2: 초안 생성 (Draft Generation)
**Goal**: 주제 한 줄이나 기존 카드뉴스 원고를 주면 릴스 원고 JSON 초안과 게시글 문구·해시태그를 받는다. 원고는 하우스 패턴을 따르고, 검증된 수치만 쓴다.
**Depends on**: Phase 1
**Requirements**: DRAFT-01, DRAFT-02, DRAFT-03, DRAFT-04, DRAFT-05, DRAFT-06
**Success Criteria** (what must be TRUE):
  1. 주제 한 줄을 주면 릴스 원고 JSON이 나온다. 원고는 7장면 내외, 훅→비유→수치→결론→주의→CTA 순서, 약 25초 분량이고, Phase 1 렌더러로 바로 MP4가 된다.
  2. 기존 카드뉴스 원고(예: `2026/02-tax-deduction/spec.json`)를 넣으면 릴스 원고 골격이 나온다. 원본에 없는 숫자가 들어간 장면과 줄은 경고로 표시된다.
  3. 원고에 쓰인 세법·통계 수치는 모두 수치 등록부 항목(출처·기준일·확인일·시행/발의/폐지 상태)으로 거슬러 올라갈 수 있다. 등록부에 없는 수치는 걸러지고, "발의" 상태 수치는 확정처럼 쓰이지 않는다. 파생 수치는 프로그램 계산값과 일치한다(기존 편 수치 재현 시험 포함).
  4. 원고와 함께 게시글 문구(훅, 핵심 요약, 근거, 일반 정보 고지, CTA)와 해시태그 5개 이하가 나온다. 시리즈명·회차·다음 편 예고를 지정하면 원고(첫 장면 화면 포함)와 게시글 문구에 같은 값이 들어간다.
  5. 버전 표시 없는 기존 원고 10편은 고치지 않아도 그대로 읽히고, 렌더 결과도 바뀌지 않는다. 새 선택 항목(시리즈·모션·수치·구조화 근거)을 쓴 원고도 같은 명령으로 읽힌다.

### Phase 3: 점검과 검수 묶음 (Compliance & Review Bundle)
**Goal**: Claude Code 세션에서 한 번 요청하면 10분 안에 검수 가능한 초안 묶음을 받는다. 단정 표현과 근거 없는 수치는 빠짐없이 표시되고, 사람이 승인하기 전에는 아무것도 정식 경로로 나가지 않는다. 이 단계가 끝나면 제작 자동화(1순위)가 완성된다.
**Depends on**: Phase 2
**Requirements**: COMP-01, COMP-02, COMP-03, COMP-04, COMP-05, COMP-06, BNDL-01, BNDL-02, BNDL-03, BNDL-04, BNDL-05, BNDL-06, BNDL-07
**Success Criteria** (what must be TRUE):
  1. "이 주제로 릴스 만들어 줘"라고 한 번 요청하면 `2026/reels/drafts/<게시일>-<슬러그>/`에 원고, MP4, 표지 PNG, 게시글 문구, 점검표가 생긴다. 주제 입력부터 묶음 완성까지 걸린 시간이 실측으로 기록되고, 10분 이내다.
  2. 점검표는 원고·근거·게시글 문구·해시태그를 모두 본다. 단정·보장 표현, 세무 단정, 상품 권유, 근거 없는 비교·비방, 개인정보는 "수정 필요"로 표시된다. 근거·기준일 없는 수치, 예시·가정 표기 누락, 세무사 확인 안내 누락, 미래 보장 아님 고지 누락은 "확인 필요"로 표시된다. 각 항목에는 장면·줄 번호, 문제 표현, 사유, 대체 표현 제안이 붙는다. 결과 머리말에는 "통과"가 없고, "위험 표현 n건 발견" 또는 "패턴상 발견 없음 — 사람 검수 필요" 중 하나만 규칙 버전·기준일과 함께 나온다.
  3. 데이터 파일의 점검 규칙을 추가·수정하면 코드를 바꾸지 않아도 다음 점검에 반영된다. 기존 10편과 레드팀 사례(부적절 30건 이상, 적절 15건 이상)에 대한 탐지율·오탐 보고서를 볼 수 있다.
  4. 검수 요약 문서 하나에 상태 배너, 점검 결과, 사람 확인 목록(수치 재확인, 기준일, 표지 크롭, 음원 라이선스, 개인정보), 광고 해당 여부·심의 상태(초안/내부 검수/승인)·심의번호 기록 칸이 있다. 기록 칸은 확인 전까지 "미확인"으로 표시된다. 첫 장면 기준 표지(글자가 중앙 1080×1440 안)와 장면별 정지 화면 모음 이미지가 함께 있어 영상을 열지 않고 검토할 수 있다.
  5. 원고 수정을 요청하면 영상, 표지, 게시글 문구, 점검표가 다시 만들어지고 점검도 다시 실행된다. 정식 경로(`2026/reels/`, `specs/`, `captions/`)로 옮기기는 승인 후에만 된다. 수정 필요 항목이 남았거나 승인 뒤 파일이 바뀌었으면 옮기기가 거부된다.

### Phase 4: 자막 연출 + 선택 배경음 (Motion & BGM)
**Goal**: 같은 원고로 줄 진입, 장면 전환, 숫자 카운트업이 들어간 보는 맛 있는 릴스를 받는다. 원하면 라이선스가 확인된 자기 음원으로 배경음을 넣을 수 있다. Phase 3 검수 묶음 흐름과 업로드 규격은 그대로 지켜진다.
**Depends on**: Phase 3
**Requirements**: MOTN-01, MOTN-02, MOTN-03, MOTN-04, MOTN-05, MOTN-06
**Success Criteria** (what must be TRUE):
  1. 모션을 켠 릴스에서 각 줄은 약 250~350ms 동안 페이드와 함께 살짝 떠오르며 나타난다. 장면이 바뀔 때는 약 0.3초짜리 전환 효과 1종이 들어가고, 모션 중에도 한글 줄바꿈 위치가 흔들리지 않는다.
  2. 원고에서 숫자를 카운트업으로 표시하면 숫자가 올라가는 효과가 나온다. 마지막 프레임의 숫자는 원고 숫자와 글자 하나까지 같다.
  3. 모션 끄기(`none`)로 만든 릴스는 Phase 1 회귀 기준과 길이·장면 경계·표지 시점이 같고, 화면도 허용 오차 안에서 일치한다.
  4. 장면 체류 시간은 글자 양에 맞춰 자동으로 정해지고, 너무 빠르거나 긴 장면은 렌더 시 경고된다.
  5. 음원 파일과 라이선스 메모를 함께 주면 배경음이 페이드인·아웃과 적정 음량으로 들어간 MP4가 나오고, 이 MP4도 업로드 규격 검사를 통과한다. 라이선스 메모가 없으면 렌더가 거부된다. 음원 파일은 저장소에 커밋되지 않는다.

**UI hint**: no
**Owner gate (Phase 4 시작 전)**: 배경음 음원 파일과 라이선스(사업자 계정 상업 사용 가능 여부, 증빙 형식). 결정 전까지 배경음은 비활성이다. 모션(MOTN-01~05)은 이 게이트와 관계없이 진행할 수 있다.
**Research flag**: 짧은 spike. `Intl.Segmenter` 자소 분리와 줄별 투명도를 적용할 때 줄바꿈이 안정적인지, 카운트업 고정 너비 박스, 클라우드 렌더 시간(장면당 3분 이하)을 확인한다. 렌더 경로 자체는 실측을 마쳤다.
